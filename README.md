# FoxCleaner

项目里积累了临时文件、旧版本和构建残留？让 AI 先理解项目，再列出候选项供你勾选，确认后移入系统废纸篓。

FoxCleaner 是面向 Codex 的文件清理 **Skill、八步工作流和 HTML 勾选清单**。扫描、分析与文件操作由运行 Skill 的 AI 助手及其可用工具完成。

> **当前状态：实验性。** 聊天中的勾选结果自动回传尚未通过验收，完整自动衔接流程仍需修复。请先在临时测试目录中试用；未收到有效选择结果时，不应继续文件操作。

## 能做什么

- **先理解，再筛选**：结合项目用途检查重复文件、旧版本、临时文件、相似图片、工具缓存和实验残留等 13 类内容。
- **逐项确认**：每项附一句用途说明；默认不勾选，支持全选、取消和单独选择。
- **可恢复清理**：工作流要求仅将确认的项目移入原生废纸篓或回收站。失败项停止处理，不改用永久删除，也不自动清空废纸篓。
- **按需扩大范围**：选择 `archived` 模式后，才额外检查依赖、虚拟环境和构建产物。这个模式不代表备份或归档。

移入废纸篓通常不会立即释放磁盘空间；是否清空由你另行决定。

## 安装与使用

将仓库下载或克隆到 Codex 的 Skill 目录，文件夹命名为 `file-cleaner`。例如使用 `~/.codex/skills/file-cleaner/`，其中应直接包含 `SKILL.md`、`WORKFLOW.md`、`agents/` 和 `assets/`。已有同名 Skill 时先检查内容，避免覆盖自己的修改。

在能识别该 Skill 的 Codex 聊天中输入：

```text
使用 $file-cleaner 检查我指定的临时测试目录，先只读扫描并展示清单，等待我确认。
```

提供目录后，助手会按工作流询问是否进入 `archived` 模式，再生成勾选清单。项目以外的工具数据只有在你明确指定范围后才纳入检查。

聊天清单依赖宿主提供 HTML 展示能力和 `window.openai.sendFollowUpMessage` 接口；文件操作还需要系统原生废纸篓机制及相应权限。完整步骤见 [WORKFLOW.md](WORKFLOW.md)。

### 只看界面

用现代浏览器打开 [index.html](index.html)，即可体验全选、逐项勾选和提交。这个页面使用演示数据，提交只把选项写入地址栏，不会清理文件，也不会回传聊天。

## 已验证与待解决

测试仅使用临时目录中的合成文件：

- 浏览器预览：默认不选、全选、取消和只提交所选两项均已验证。
- macOS 原生操作：用户确认前两项后，使用 Finder 将测试文件和目录移入废纸篓，再通过“放回原处”恢复。恢复后的 7 个测试文件逐字节一致；第三项及其他未选文件未被移动。
- **聊天自动回传未通过**：点击提交后，聊天未收到预期的 `project`、`archived` 和 `paths` 数据。因此上述原生操作验证不代表自动端到端流程已通过。
- Windows、Linux 的原生回收与恢复尚未实测。
